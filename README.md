# ⚔ Steel Arena — 3D Browser Fighting (prototype)

**Играть:** https://gptvikgpt-code.github.io/Steel-Arena-/

Steel Arena — самостоятельный браузерный файтинг с мультяшной 3D-графикой, созданный для игры с другом на Android, iPhone или компьютере. Это оригинальный проект, не копия чужих исходников, брендов, персонажей или графических ресурсов.

## Реализовано

- 6 оригинальных бойцов: Ронин, Страж, Тень, Арканист, Титан, Копейщик
- Три режима: классическая дуэль, бесконечный ринг без стен и таймера, арена с повторяющимися платформами
- 3 процедурно созданные 3D-арены: Храм, Роща и Город, с повторяемым фоном и полом
- Плавная камера, которая следует за бойцами и увеличивает охват по мере их удаления друг от друга
- 6 видов оружия на выбор независимо от героя: меч, топор, копьё, посох, кинжалы, молот; у каждого собственная 3D-модель, сила, дальность и скорость
- Базовая боевая система: простой/сильный удар, блок, короткое окно парирования, рывок, прыжок, спецприём и суперудар
- Различия между героями по скорости, силе и дальности
- Серия до 2 побед, таймер, здоровье и накопление энергии
- Тренировка против бота
- Сенсорные кнопки для телефонов и управление клавиатурой
- Бета-система сетевых комнат WebRTC (PeerJS, публичный сервер сигнализации)

## Как начать

Открой ссылку, выбери героя, оружие и режим и нажми **БОЙ С БОТОМ**. Для боя с другом создай онлайн-комнату и отправь ссылку через **КОПИРОВАТЬ**. Друг открывает ссылку на своём телефоне, вводит шестизначный код и нажимает **ВОЙТИ**. Играть удобнее в горизонтальной ориентации.

**Клавиатура:** A/D движение, W прыжок, J лёгкий удар, K сильный удар, S блок, Shift рывок, L спецприём, P суперудар.

## Ограничения

Это ранний **прототип**, а не законченная игра уровня коммерческого файтинга. Пока нет кампании, боёв на 4 человека, полноценного матчмейкинга, сервера с авторитетной физикой, сохранений, рейтингов и каталогов анимаций. Выбранное оружие передаётся между игроками при создании сетевой комнаты. Базовая онлайн-связь использует STUN и требует теста на двух реальных устройствах. Для сетей с ограничительным NAT добавлена ручная настройка временных TURN-учётных данных на каждом устройстве; сам TURN-сервис и учётные данные проект не предоставляет.

Внешние зависимости: Three.js 0.169.0 и PeerJS 1.5.5 загружаются из публичных CDN. Отсутствие доступа к CDN мешает запуску.

## Настройка TURN для ограничительных сетей

В главном меню раскрой **«Дополнительно: TURN для сложных сетей»**. Если прямое соединение не устанавливается, каждый игрок отдельно вводит выданные TURN-провайдером адреса, временный username и credential. Значения остаются только в полях текущей страницы: они не сохраняются в localStorage и не добавляются в ссылку-приглашение. Не используй постоянные пароли или случайные публичные TURN-узлы. Флажок **«Использовать только TURN»** предназначен для отдельной проверки релея; его нужно включить у обоих игроков. Без действующего TURN-провайдера эта настройка сама по себе не создаёт ретранслятор.

## Автоматические проверки

GitHub Actions запускает три разных типа проверок:

1. **Browser checks (`verify.yml`)** — локальная браузерная проверка в одном GitHub Actions runner. Playwright открывает Chromium с Android-подобным сенсорным профилем и WebKit с iPhone-подобным профилем, проверяет загрузку настоящего 3D-рендера, сетевые комнаты, оба тестируемых режима, наличие элементов управления, передачу движения и двустороннюю проверку попаданий: каждый клиент наносит урон, а второй получает авторитетное состояние здоровья. Отдельно Playwright Touch API выполняет касания джойстика и кнопки действия и проверяет `pointerType="touch"`; длительное движение и удержание атаки в боевом сценарии по-прежнему моделируются программными `PointerEvent`. Во время самой сетевой симуляции `graphics.js` заменяется облегчённым адаптером, чтобы программный WebGL не искажал таймеры теста.

2. **Cross-runner WebRTC (`cross-network.yml`)** — хост и гость запускаются на отдельных GitHub-hosted Ubuntu 24.04 runner-машинах: Chromium для хоста и WebKit для гостя. Отдельно проверяются режимы `duel` и `platform`, подключение через PeerJS/WebRTC, передача движения и синхронизация урона. Для воспроизводимости тест подменяет генератор кода комнаты фиксированным шестизначным кодом; в сетевой части также используется тестовый графический адаптер. Playwright Touch API отдельно подтверждает, что джойстик и кнопка действия получают `pointerType="touch"`, но движение и удержание атаки в боевом сценарии всё ещё запускаются программными `PointerEvent`.

3. **Published-site smoke (`live.yml`)** — проверяет, что опубликованный `game.js` совпадает с исходником проверяемого коммита, а затем запускает браузерную проверку непосредственно против URL GitHub Pages. Два клиента в этой проверке работают на одном runner-машине, не на физических телефонах.

Эти проверки полезны для регрессии и подтверждают работу браузерного протокола в тестовых окружениях. Но они **не являются сертификацией Android ↔ iPhone**: профили Playwright не являются настоящими телефонами, программные `PointerEvent` не являются физическими касаниями, а отдельные GitHub runner-машины не моделируют мобильные сети разных операторов и стран. Успешный CI или публикация GitHub Pages сами по себе не доказывают, что матч пройдёт на любых двух сетях.

## Критерий готовности

**Не объявлять игру готовой**, пока не пройдёт полный бой на двух физических устройствах — Android и iPhone — в разных местах и через разные интернет-подключения. Нужно проверить открытие опубликованной страницы, создание комнаты и ввод шестизначного кода, двустороннее сенсорное управление, видимые обоим игрокам попадания и здоровье, оба режима, завершение матча, победу и повторный матч.

Сейчас клиент использует публичную сигнализацию PeerJS и STUN-серверы, но не имеет собственного TURN-релея. Для сетей с ограничительным NAT прямой WebRTC может не соединиться; надёжный TURN требует отдельной серверной инфраструктуры и выдачи временных учётных данных.

## Дальнейшая разработка

1. Получить безопасный TURN-сервис и выдать каждому игроку временные учётные данные; проверить принудительный relay-маршрут на двух физических устройствах.
2. Испытать бой Android ↔ iPhone через разные мобильные сети.
3. Устранить задержку ввода, улучшить прогноз движения и стабильность соединения.
4. Ввести полноценные уникальные наборы приёмов, серии комбо, звуковую систему и дополнительные анимации.
5. Заменить процедурных бойцов качественными оригинальными моделями и добавить новые режимы.
